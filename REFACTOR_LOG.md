# StoryCore multi-story refactor — log (11–12 November 2026)

Goal: turn the single-story app (Lumencia Academy) into a multi-story engine that loads any lore pack without code
changes. Each phase kept Lumencia's behaviour identical (checked by comparing the narrator context before and after),
and has a backup folder `_backup_phaseN` with the original files and a README explaining how to undo it.

## Phase 0 — repair (the app did not start)
- Release build shipped pre-compiled files (`__pycache__`) that Python ran instead of the source, so edits never took
  effect. `Start StoryCore.bat` now runs Python with `--check-hash-based-pycs always`.
- Removed a stray `<EOF>` line (`world_state.py`); added migration 0006 (`worlds.stats_template`, `roles` table);
  backend accepts both client header names; `lumencia.db` is copied once to `stories.db`; stored lore/portrait paths
  are found again under `Lorepack/`.

## Phase 1 — the lore pack format
- `pack.json` at the root of each pack (`LOREPACK_FORMAT.md`), read and checked by `services/pack_manifest.py`.
- `pack.json` written for Lumencia (all data that was hard-coded) and Hero's Chronicle.

## Phase 2 — the engine reads pack.json
- Posts, closed groups, facts, class rosters, places, never-random types, calendar, stats and openings come from the
  pack; `services/world_pack.py` is the single accessor. In-app corrections are layered on top (before, one correction
  wiped out all the defaults). Migration 0007 removes the old "Enrollment" copy from the global openings.

## Phase 3 — the `school` module
- Lesson detection, first-year encounters, start-of-year date and student wording only for packs with
  `"modules": ["school"]` (or gatherings of kind `class`); neutral wording otherwise.

## Phase 4 — automatic loading
- At every start, every folder in `Lorepack/` with a `pack.json` is imported if new, re-imported if its files changed,
  and its portrait folder registered and scanned. Broken packs and duplicate ids are skipped with a log message.

## Phase 5 — frontend (compiled; patched directly)
- Renamed to StoryCore; sends `X-Story-Client`; new "World default" stat sheet (the world's own stats); export file
  names `storycore-*`. Patched bundle: `app/frontend/dist/assets/index-storycore-p5.js` (new name so browsers reload it).

## Phase 6 — Hero's Chronicle playable
- Lore import made tolerant of other pack layouts (ids from names, unknown lists categorised by file name,
  object-shaped files): Hero's Chronicle went from 19 to 48 lore records (factions, cities, power systems, glossary,
  2 openings). Lumencia unchanged (116 records).
- Provisional Hero `pack.json`: description, stats, 2 openings, 9 posts from character types, Demon King never random.

## Phase 7 — cleanup
- Fixed broken full backups (verify/restore failed since the earlier refactor) and made files exported by Lumencia
  Story Desk importable again (story packages, full backups, notes, local canon, commands).
- StoryCore branding in the backend, launcher, README and START_HERE; removed the unused `ACTIVE_WORLD_SLUG` setting;
  moved the unused `academy_facts.json` to `_to_delete/`; rewrote `ARCHITECTURE.md`.

## Final check (12 November 2026, real app on Windows via screen control, local model rocinante-12b in LM Studio)
- `Start StoryCore.bat` starts the app; both packs load automatically with their portraits.
- Lumencia: new story through the wizard (Enrollment, World default stats), opening scene and one turn generated by the
  local model; portraits, scene cast and suggested replies work.
- Hero's Chronicle: its own openings offered (no Enrollment), opening scene generated by the local model.
- Fixed during the check: the home page no longer suggests registering the whole `Lorepack` folder (its packs' portrait
  folders are already registered); the "research-based reference pack" notice is now the optional `canon_note` of a
  pack (kept for Lumencia only).
- Test stories created in your library: "[StoryCore test] Lumencia" and "[StoryCore test] Hero" (delete them when you like).

  described as the god Lily). Not changed; posts were based on `type`.
- 6 Hero portrait files match no character id.
- Your old install `Documents\LumenciaStoryDesk` still exists, so its two portrait folders stay registered next to the
  new `Lorepack` ones (same images, harmless). Remove them in **Portraits** if you no longer use that folder.
- Kept for compatibility on purpose: reading `lumencia.db`, old export formats, the `X-Lumencia-Client` header, the
  "lumencia" stat-sheet name.

## Left as is (harmless)
- The `roles` database table added by the earlier refactor is unused. `data/bundled_resources.json` is no longer read.
- Old compiled `__pycache__` folders are ignored at start; they can be deleted.
- Folders to delete by hand when convenient: `_to_delete/`, the `_backup_phase*` folders once you are satisfied,
  `_backup_phase2/_journal_to_delete`, and the empty `app/backend/story/data/`.

## Final step (12 November 2026) — v1.7.0
- Hidden information: `"hidden"` fields in lore are narrator-only secrets (see `LOREPACK_FORMAT.md`).
- Hero's Chronicle: new opening "The Summoned Hero" (the author's prologue with Lily); openings can now set their
  starting scene (`starters[].scene`: place, time, date, who is present); the narrator reads dates with the world's
  year label ("Imperial Calendar 1301").
- `DEVONLY/`: full developer documentation and `make_release.py` (clean shareable ZIP).
- README, START_HERE and release notes updated (LM Studio, two worlds); version 1.7.0.
- Portrait tags ("image triggers"): the narrator writes [Name:N] (N = 1 neutral, 2 happy, 3 sad, 4 angry, 5 disdain,
  6 love/shy) before a spoken line; the app hides the tag and shows name_N.webp as soon as the reply ends. The scene
  analysis still completes untagged speakers and reactions and never overrides a tag. Suggested replies off by default.
- Release check: the ZIP was extracted to a new folder and started with the .bat on Windows; LM Studio connected
  through the app's own dialog; the Summoned Hero opening, a turn, portraits, the date header and a verified backup
  all worked.
