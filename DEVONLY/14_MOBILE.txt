STORYCORE MOBILE (Android, APK autonome)
========================================

Principe : UN SEUL CERVEAU
--------------------------
L'APK embarque le même moteur Python que le PC (app/backend), sans copie à la main.
Python tourne dans l'application grâce à Chaquopy (https://chaquo.com/chaquopy/).
Au démarrage, le moteur écoute sur http://127.0.0.1:8765 (sur le téléphone lui-même),
et une WebView plein écran affiche l'interface.
=> Toute modification de app/backend ou de Lorepack/ touche le PC ET le mobile.

Où est quoi
-----------
mobile/android/                      projet Android (coquille)
  app/build.gradle.kts               réglages : version de Python, bibliothèques, ce qui entre dans l'APK
  app/requirements-mobile.txt        bibliothèques du moteur pour Android (mêmes versions que le PC, sauf Pillow)
  app/src/main/python/mobile_boot.py démarre le moteur (équivalent de scripts/serve.py)
  app/src/main/java/.../MainActivity.kt   écran de l'app : démarrage, WebView, page d'erreur
  app/src/main/java/.../AssetSync.kt      copie interface + Lore packs + musique sur le téléphone
mobile/tools/build_wheel.py          compile pydantic-core pour Android
.github/workflows/mobile-apk.yml     compilation automatique sur GitHub

Sur le téléphone (stockage privé de l'app)
------------------------------------------
files/storycore/Lorepack, Music, web   recopiés depuis l'APK au 1er lancement et après chaque mise à jour
files/storycore/data                    base, sauvegardes, clés API (data/secrets.json) : jamais touché par une mise à jour

APK FINALE (se met à jour toute seule)
-------------------------------------
C'est celle que tout le monde installe. Elle est fabriquée AUTOMATIQUEMENT à chaque version publiée :
1. Pousser sur GitHub (DEVONLY\Push vers GitHub.bat). Obligatoire : l'APK est fabriquée à partir du code EN LIGNE
   (publish.ps1 refuse de publier s'il reste des modifications non poussées).
2. Changer APP_VERSION (app/backend/story/config.py) puis lancer DEVONLY\Publier une mise a jour.bat.
   -> la version vX.Y.Z est publiée (installateur PC) ; GitHub Actions ("Mobile APK", job "APK (final)")
      fabrique alors StoryCore-X.Y.Z.apk, signée avec la clé SECRÈTE, et l'ajoute à cette même version (~10 min).
3. Sur les téléphones : à chaque démarrage, Updater.kt lit https://github.com/kurioman/StoryCore/releases,
   prend la version publiée la plus récente qui contient une .apk, et si elle est plus récente propose
   « Mettre à jour » -> téléchargement -> écran Android « Mettre à jour cette application ? ».
   La 1re fois, Android demande d'autoriser StoryCore à installer des applications (réglage « Autoriser depuis cette source »).
   Parties, Lore packs modifiés et clés API sont conservés (dossier data jamais touché).
Clé secrète : _release/signing (sur le PC, JAMAIS dans git) + 2 GitHub Secrets STORYCORE_KEYSTORE_B64 et
STORYCORE_KEYSTORE_PASSWORD (voir _release/signing/LISEZ-MOI.txt). SANS CETTE CLÉ, PLUS AUCUNE MISE À JOUR POSSIBLE
pour les téléphones déjà installés : garder une copie de sauvegarde (clé USB, cloud).
Numéro de version Android : 0.7.3 -> versionCode 7003 (toujours croissant).
L'APK de test et l'APK finale ont des clés différentes : passer de l'une à l'autre oblige à désinstaller
(exporter d'abord ses parties et ses Lore packs).

APK de test (Compiler l'APK à la main)
--------------------------------------
1. Pousser sur GitHub (DEVONLY\Push vers GitHub.bat).
2. GitHub > dépôt StoryCore > onglet Actions > "Mobile APK" > bouton "Run workflow".
3. Attendre (1re fois ~20-30 min car pydantic-core est compilé ; ensuite il est réutilisé, ~5-10 min).
4. Ouvrir l'exécution terminée > "Artifacts" > StoryCore-mobile-apk (un .zip qui contient l'APK).

Points d'attention
------------------
- pydantic-core n'existe pas en version Android : build_wheel.py le compile. Si on change la version de
  pydantic, changer aussi pydantic-core dans requirements-mobile.txt ET PYDANTIC_CORE dans mobile-apk.yml.
- Le moteur ne doit jamais dépendre de Windows sans garde-fou (comme hardware.py, installer.py, keyring).
- Téléphones pris en charge : Android 7.0+ en 64 bits (arm64-v8a). Python 3.13 n'existe pas en 32 bits sur Android.
- APK de test : signée avec une clé de TEST fixe (mobile/android/app/test-debug.keystore, publique) ;
  chaque nouvelle APK de test s'installe par-dessus l'ancienne sans perdre les parties.
  La première APK (test n°1) avait une autre clé : il a fallu la désinstaller une fois.
  Pas de mise à jour automatique (BuildConfig.SELF_UPDATE = false). L'APK finale a sa propre clé secrète (voir plus haut).
- Images : le Pillow Android de Chaquopy ne lit pas le WebP. android_webp.py branche le décodeur WebP
  d'Android dans Pillow (lecture, vignettes, enregistrement) ; le moteur partagé n'en sait rien.

Mode mobile de l'interface (Phase 1)
------------------------------------
- UNE SEULE interface (app/frontend) pour le PC et le mobile. L'app ajoute "StoryCoreAndroid/<version>" au
  user agent ; lib/remote.js en déduit IS_ANDROID_APP (et IS_PHONE = app Android OU téléphone en Wi-Fi).
  <html data-platform="android|phone"> permet d'adapter les styles.
- Masqué dans l'app : onglets Ollama et « Play on a phone », choix local/en ligne (assistant et réglages),
  modèles locaux dans « Ajouter un fournisseur », « Open data folder ».
- Fichiers : <input type=file> -> sélecteur Android (FileTransfers.chooserIntent) ; téléchargements du moteur
  (DownloadListener) et fichiers faits par l'interface (lib/util.js saveBlob -> window.StoryCoreAndroid.saveFile)
  -> écran « Enregistrer sous » d'Android. Aucune permission de stockage nécessaire.
- Tout se fait au doigt : chaque fenêtre a son bouton ✕ ; le bouton Retour d'Android n'est qu'un raccourci
  (ferme la fenêtre ouverte, sinon revient en arrière).
